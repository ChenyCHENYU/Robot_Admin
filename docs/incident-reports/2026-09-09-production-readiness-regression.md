# 2026-09-09 生产就绪优化回归事故报告

## 事故结论

本次问题属于严重的前端完整性回归。问题不是业务功能自然失效，而是在生产化和组件库接入调整中，没有先建立现有行为与呈现基线，错误地把“未理解的现有能力”当成可裁剪项，同时混用了自动解析、手动导入和依赖预构建策略。结果覆盖登录、导航头部、图标、认证持久化、动态路由和多个深层演示页面。

本次修复坚持恢复既有能力，不重做视觉、不更换交互、不扩展业务范围。对照 `origin/main`、问题提交和当前产物后，确认共有 11 类退化或高风险点；运行时代码没有被整页删除，但存在功能开关、样式入口、图标生成和加载链路被切断，实际影响等同于功能丢失。

## 根因分析

1. 没有在优化前冻结登录页、头部弹层、认证持久化和动态路由的行为基线。
2. 把组件“可被导入”误当成组件“样式和运行时依赖也已完整接入”，忽略 resolver `sideEffects` 只对自动解析生效。
3. 把减少依赖预构建理解为完全放弃深层依赖互操作，没有逐路由验证组件包内传递依赖。
4. 启动优化同时引入多套预热手段，且没有用冷启动、热启动和首次登录导航三个独立指标验收。
5. 类型通配声明掩盖了真实接口问题，导致静态检查未能提前暴露部分风险。

## 修复与防复发措施

- 新增 `tests/ui-regression-contract.test.ts`，固定登录能力、演示凭据、背景兜底、5 个头部组件样式、手动组件样式、17 个运行时图标、代码高亮、导航非阻塞和依赖互操作契约。
- 删除遮蔽 Naive UI 的通配声明，应用与 Vite 配置均进入真实类型门禁。
- 自动解析组件统一交给官方 resolver；确需运行时手动导入的组件必须同位置显式导入样式，避免多个隐式事实源。
- 依赖预构建采用“标准 ESM 重包保持懒加载、已确认 CJS 桥接依赖精确包含”的边界，禁止再次添加全量页面预热。
- 普通 `dev` 不运行同步 Git 横幅；需要分支信息时显式使用 `dev:banner`。
- 后续涉及视觉或交互删改，必须先获得业务确认，并至少覆盖登录、首页、全部头部弹层和全路由浏览器巡检。

## 责任与后续边界

本次事故由优化过程缺少完整基线和错误裁剪造成。后续不再以“代码更少”作为单独成功标准；只有现有功能、交互、样式、启动、导航、类型、构建和全路由运行均通过，才视为优化完成。Element Plus、移动端或新能力扩展不属于本次修复范围。
