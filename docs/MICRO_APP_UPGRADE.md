# micro-app 分支升级说明（2.6.3）

此分支保留 `@micro-zoe/micro-app` 容器和门户架构，同时同步单体主线 2.6.3 的页面、插件版本、构建、类型检查、安全头及测试基线。它不是把单体 `main` 合并到微前端分支；智慧物流仍是独立仓库，须单独升级和部署。

## 环境与启动

- Bun ≥ 1.4.2，Node.js ≥ 22.18；先运行 `bun ci`。
- 主应用：`bun run dev`，固定在 `http://127.0.0.1:1988`。
- 本地智慧物流子应用：自行启动独立项目，并在 `envs/.env.development` 配置 `VITE_MICRO_LOGISTICS_URL=http://127.0.0.1:3003`。
- 生产和预发环境**没有默认子应用地址**。部署时通过对应环境的 `VITE_MICRO_LOGISTICS_URL` 指向自己控制的 HTTPS 站点，再重新构建。未配置或地址不合规时，门户会标记“待集成”，访问容器页会明确提示，而不是加载示例域名。
- 只允许 HTTPS；仅开发模式允许 localhost、127.0.0.1 或 `[::1]` 的 HTTP。不要在 URL 中放账号、密码、令牌或 fragment。

## 信任边界

子应用代码会在主应用的微前端沙箱中执行，因此配置的远端地址是**代码信任边界**。仅部署自己控制、经过审核的子应用；CORS、HTTPS 和 iframe 沙箱都不能代替代码审计。认证数据只传给显式配置的子应用，不向未配置 URL 发送。传递数据限定为可序列化值；不再跨应用传 Vue 组件、函数或消息实例。

主应用收到 `postMessage` 时同时核对实际微前端 iframe 窗口及该 iframe 的来源，校验消息结构和导航路径；确认消息使用核对后的精确 `targetOrigin`，不使用 `*`。注意该框架的 iframe 沙箱在主文档中，消息来源通常是沙箱所在的主应用 origin，而非远端资源 URL。若要扩展消息协议，先更新这两个校验，再添加浏览器回归测试。

## 本地验证

```sh
bun run verify
bun run security:audit
bun run test:e2e
```

`verify` 包括静态检查、生产构建、类型检查、单测、体积预算与业务构建。浏览器回归验证登录、主应用页面、门户与未配置子应用时的安全行为。联调智慧物流仍需启动其独立仓库并人工核验真实子应用页面、认证与通信；本仓库的测试不代表该仓库已升级。

此分支不提供把自身合并到 `dev`/`main` 的 deploy 命令。完成验证后只快进并推送 `micro-app`，避免把微前端目录、路由或部署假设带入单体分支。
