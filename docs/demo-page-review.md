# 演示页逐页审阅与使用侧治理

范围是 `src/views/demo` 的 64 个 `index.vue`（含 C_Form 八种布局），消费已安装的 `@robot-admin/naive-ui-components@0.12.1`。本轮检查组件调用、数据来源、异步生命周期、类型、无效事件监听、演示文案及构建行为。未改的页面只表示本轮静态审阅未找到需要立即修复的使用侧问题，不代表后端契约或组件内部实现已被证明完美。

所有 64 页现在均声明唯一 PascalCase 组件名，并由 `tests/demo-conventions.test.ts` 守护。复杂页面按“演示容器与组件配置分离”评估：代码行数不直接等于组件使用复杂度；场景本身需要多个交互时，不为了缩短文件而折损演示能力。

## 仍需在组件包处理的边界

- C_Form 的动态/标签/步骤布局仍有较多“事件转发 + 手写控制栏”样板。若要进一步缩短真实使用页，应先在组件包提供强类型的布局动作插槽和统一 `{ model }` 提交契约，再逐页迁移；本轮不修改已发布包，也不在项目侧伪造新 API。
- C_VtableGantt 导出的 `GanttTask`、`GanttOptions` 与实例 `ganttInstance` 仍包含宽泛类型，VisActor 的 `Group.add` 参数和自身 `Group` 类型在当前依赖图不完全一致。本轮把兼容断言集中在页面边界，真正消除需在组件包和上游版本配套治理。
- 08/11/12/38/40 等页的延迟与“成功”主要是交互模拟；连接后端前必须替换为真实服务调用，不能把演示成功视作持久化保证。

## 验证入口

`bun run verify` 检查静态规则、类型、单元测试、构建和包体预算；`bun run test:e2e` 检查正式构建中的关键演示路由和原有认证/地图流程。Excel 空行、表格复制和所有演示页命名分别有独立回归测试。
