# 演示页逐页审阅与使用侧治理

本文前半记录 **2026-09-30、组件包 0.13.0 的历史阶段**，其中的“本轮”“现在”和待处理事项均属于当时结论。当前正式包接入状态见文末的 [2026-10-18 · 0.15.0 接入复核](#review-015-20261018)。

## 2026-09-30：0.13.0 历史阶段

范围是 `src/views/demo` 的 64 个 `index.vue`（含 C_Form 八种布局）。正式构建消费已安装的 `@robot-admin/naive-ui-components@0.13.0`；另外用 `bun run test:e2e:local-components` 对同级目录组件源码执行浏览器回归。本轮检查组件调用、数据来源、异步生命周期、类型、无效事件监听、演示文案及构建行为。未改的页面只表示本轮静态审阅未找到需要立即修复的使用侧问题，不代表后端契约或组件内部实现已被证明完美。

### 当时仍需在组件包处理的边界

- C_Form 的动态/标签/步骤布局仍有较多“事件转发 + 手写控制栏”样板。若要进一步缩短真实使用页，应先在组件包提供强类型的布局动作插槽和统一 `{ model }` 提交契约，再逐页迁移；本轮不修改已发布包，也不在项目侧伪造新 API。
- C_VtableGantt 导出的 `GanttTask`、`GanttOptions` 与实例 `ganttInstance` 仍包含宽泛类型，VisActor 的 `Group.add` 参数和自身 `Group` 类型在当前依赖图不完全一致。本轮把兼容断言集中在页面边界，真正消除需在组件包和上游版本配套治理。
- 08/11/12/38/40 等页的延迟与“成功”主要是交互模拟；连接后端前必须替换为真实服务调用，不能把演示成功视作持久化保证。

### 当时的验证入口

`bun run verify` 检查静态规则、类型、单元测试、构建和包体预算；`bun run test:e2e` 检查正式构建中的关键演示路由和原有认证/地图流程。`bun run test:e2e:local-components` 使用同级组件源码，复用浏览器回归并增加城市键盘选择、代码全屏退出交互测试；该模式只供集成验证，正式构建仍禁止本地包 alias。Excel 空行、表格复制和所有演示页命名分别有独立回归测试。

## 2026-10-18：0.15.0 正式包接入复核

本次将依赖精确升级为 `@robot-admin/naive-ui-components@0.15.0`，同步 Bun 锁文件并完成冻结安装。正式消费来自 npm registry 的发布包，已核对包完整性及依赖元数据，未用兄弟仓库源码 alias 替代。项目 MCP 对正式安装包重新查询全部 55 个组件 API；使用侧适配以发布声明和实际实现为依据。

### 使用侧约定

- 需要组件等待结果、维护 loading 或决定是否完成保存的任务，返回完整 Promise，放在 `config.onSubmit`、`config.onSearch`、`edit.onSave` 或 ActionBar 的 `onClick`。`submit`、`search`、`save` 等 emits 用于通知，不在回调和通知中重复执行同一请求。
- 表单与搜索使用一份模型；动态表格使用 `v-model:data` 接收组件修改。仍然正确的响应式对象适配、类型导入和同步通知保持原有形式，不为统一写法制造第二份状态。
- 表单自身的 `isSubmitting` 用于按钮和字段禁用，不能反馈为该表单 `config.disabled`，否则提交校验后的可用性检查会取消任务。外部数据加载、权限等业务禁用继续保留。
- 运行时依赖使用组件子入口，合法的 type-only 根入口导入保留。静态模板组件继续由 resolver 按需注入样式；手工渲染组件显式携带组件样式，动态编辑器样式保持在对应路由。
