# `perf/production-readiness` 与 `main` 对比报告

> 对比基线：`origin/main`；当前分支：`perf/production-readiness`；日期：2026-09-09。

## 结论

当前分支在依赖治理、首屏体积、类型边界、安全配置、请求一致性和自动化门禁上明显优于 `main`，但改动面达到 221 个文件、19 个提交，回归半径也显著增大。本轮已经实际暴露登录、布局、头部样式、引导、导航、地图和异步组件生命周期等严重回归，说明此前的浏览器验收标准不足。

因此结论不是“当前分支天然比 `main` 稳定”，而是：修复并通过新的完整门禁后，当前分支更适合作为后续技术基线。`main` 的优势是既有呈现与交互经过实际使用验证，当前分支的优势是工程能力和运行边界更清晰。本轮修复后的静态、开发态和正式产物门禁均已通过。

## 当前分支的实际优势

1. **首屏与启动边界更清晰**：Markdown、文件工具、Spline、图表和动态页面按路由加载；普通 `dev` 不再同步计算 Git 横幅，也不叠加重复 warmup。
2. **生态包接入可复现**：Robot Admin 自有包使用精确版本；组件运行时走 `/C_*` 深层入口，根入口只用于显式类型导入；布局统一 `/naive` 入口。
3. **请求状态更可靠**：请求实例、认证恢复、Remote/Mock 边界和“仅最新响应生效”策略统一，快速搜索或翻页时旧响应不会覆盖新状态。
4. **生产安全能力补齐**：增加环境 Schema、部署档位、CSP/HSTS/Referrer/Permissions Policy、同源错误上报与敏感字段脱敏。
5. **主题和布局职责更明确**：主题初始化、布局桥接、宿主能力与包内能力分层，减少应用侧重复转换与多个事实源。
6. **质量门禁更完整**：除 Oxlint、ESLint 和双 TypeScript 门禁外，还包含测试、生产构建、包体预算、冻结锁文件及包发布契约。

## 已识别的代价与剩余风险

- 本轮事故证明“能编译、能打开路由”不能代表呈现和交互完整。新的浏览器门禁必须采集错误消息并断言组件实际就绪。
- 开发态首次进入 AntV X6 和 Markdown 编辑器分别需要转换约 931 和 1,937 个请求，实测 4.27 秒和 10.03 秒；这两页功能正常，但超过 2 秒冷路由预算。直接把重依赖加入启动预构建会把成本转移到每次启动，不应在缺少真实访问频率数据时贸然处理。
- 最大异步 chunk 仍为约 2.13 MiB，主要来自 VisActor；它没有污染首屏，但仍需保持预算监控。
- CommonJS 桥接清单目前是显式维护的，新增深层组件依赖时必须同步契约测试；本次 Leaflet 遗漏即是反例。
- 组件库个别历史文件格式不统一，触碰时可能产生较大的格式化差异，后续应避免把机械格式化与行为修复混在同一提交。

## 本次页面验证

- 地图：4 个 Leaflet 地图实例就绪，无 `map is not a function` 和错误消息。
- 二维码：全新浏览器首次路由解析 186ms，5 个二维码 640ms 内完成绘制，无错误消息。
- 甘特图：首次加载中立即离开页面，无失效容器初始化异常。
- 全路由：127 条路由均可达，0 个运行时异常、0 个组件错误消息；125 条满足 2 秒冷路由预算，2 条重型编辑器页列为性能观察项。
- 正式产物：127/127 路由通过，平均解析 79ms、P95 176ms、最大 322ms；AntV X6 与 Markdown 分别为 175ms、154ms，开发态冷转换成本没有进入生产体验。
- 巡检中的 24 次网络加载失败均来自快速离开地图后的瓦片取消、外部演示视频/站点或故意配置的错误图片示例；它们没有产生应用运行时异常或错误消息，不属于本次代码回归。
- 开发启动：依赖缓存已建立后的普通 `bun run dev` 本机启动为 4.06 秒；显式 `--force` 重建全部依赖缓存为 7.66 秒，两者不可混作同一指标。当前普通启动已回到原有约 3–4 秒量级边缘，后续只以普通冷/热启动持续观察。

## 合并判断

组件包 `0.11.8`、应用静态门禁、生产构建、正式预览和全路由浏览器复验现已全部通过，当前分支具备进入代码审查和合并流程的技术条件。后续优化应聚焦已测量的瓶颈，禁止以删除现有功能、全量预构建或扩大首屏依赖来换取局部数字。
