# 2026-10-08 项目报告复核与整改

复核基线：`Robot_Admin` 的 `c0e3c50`，应用 `2.7.0`，组件包正式版本 `0.14.2`。本次修改仅发生在本仓库，组件库实现和其他业务仓库未改动。评分是主观评价，不能代替类型、功能、构建和安全门禁。

## 原报告哪些判断成立

| 判断                                   | 核对结果与处理                                                                                                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 默认类型检查可能使用兄弟仓库           | 成立，但路径是相对路径。默认配置现已只解析 npm 产物；显式 `type-build:local` 才使用兄弟仓库类型。                                                                                                                  |
| 全量环境变量写入 `process.env`         | 成立。Vite 保持配置对象，翻译插件只接收显式配置，其他环境变量不会注入进程。服务端翻译凭据不作为客户端配置。                                                                                                        |
| 生产示例 API 依赖第三方 Mock           | 配置存在，但认证和系统管理已有本地 Mock，不能推论整个演示站必然失效。生产示例基址改为 `/api`，保留部署层同源代理约定。                                                                                             |
| scripts 与页面子组件被 ESLint 整体豁免 | 成立。恢复检查，只针对真正的 CommonJS 文件关闭 `no-require-imports`；样式编译的顺序执行保留局部说明。                                                                                                              |
| 死依赖、重复目录和未启用插件           | 成立。删除未使用的 motion-v、print-js、html2canvas 直接声明及未启用的 persistedstate、dynamic-components、打印 Hook、旧时间戳超时工具和 Element 公式常量。html2canvas 仍是组件库的传递依赖，保留其开发预构建配置。 |

## 不能照搬的结论

- `@robot-admin/form-validate` 已由 C_Form 集成，MCP 查询工具还直接读取它的规则声明。删除直接声明会依赖偶然的传递安装，故保留。
- 原自动扫描配置包含 stores、hooks、composables，“只扫描 composables”并非基线事实。现在主动收敛为只自动扫描 composables，领域 Store 和页面控制器显式导入。
- persistedstate 没有 Store 消费，不能将它算作第三套活跃持久化。删掉空插件后，用户会话与主题设置仍各自按领域处理，不把两种生命周期强行合并。
- 将 refreshToken 从 localStorage 移到 sessionStorage 不解决脚本读取风险，只缩短生命周期并改变重新打开浏览器、多标签行为。当前前端契约仍接收刷新令牌，真正的 HttpOnly Cookie 方案需要后端配合。[OWASP 说明](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)
- 每个演示页缺少 api.md 不等于违反现有全局规范。真实接口集中维护在 `src/api/` 和生产接入文档，不生成无内容的契约文件。
- README 中带日期的组件库 `0.13.5` 记录是历史事实；当前版本由 package.json/锁文件驱动，不能批量将历史版本改为最新。
- SheetJS tarball 是官方分发渠道，本轮保留固定 URL 与锁文件完整性。它是安装时的供应链依赖，不是每次页面打开都请求该 CDN。[官方安装文档](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)

## 额外锁定的代码完整性问题

原翻译合并驱动把 Git `%O`（祖先）当成当前分支，把 `%A`（当前分支）当成来源分支，也未正确写回输出。词典已分为多个语言文件，但属性规则仍指向旧 index.json。

现在规则覆盖 `lang/*.json`，驱动读入祖先、当前和来源版本，写回 `%A`。单方新增、修改和删除正常合入；同一词条的真实冲突返回非零，Git 保留双方暂存版本等待处理。实际 Git 分支合并测试覆盖这一路径。旧手动三参数 CLI 保留其明确的 ours 优先行为，与 Git 三方模式分开。

克隆仓库后执行 `bash scripts/setup-git-merge-drivers.sh` 为当前仓库配置驱动，配置不会写入全局 Git。

## 依赖安全与尚需演进的边界

MCP SDK 最低版本更新至 `1.31.0`，锁文件安装 `1.32.1`，实际 stdio 查询组件和规则成功。对应 OAuth 客户端公告在 1.31.0 修复；本项目的 stdio Server 不属于该公告的受影响调用路径，升级用于保持依赖安全基线。[MCP 公告](https://github.com/advisories/GHSA-6qxp-vccf-f47h)

2026-10-08 的 `bun audit` 仍返回两项公告：

- braces 3.0.3：开发工具链的嵌套 glob 解析风险。[公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)
- sprintf-js 1.0.3：Mammoth/argparse 与提交工具链中的格式字符串风险。[公告](https://github.com/advisories/GHSA-hp3w-g68c-fv3c)

官方公告均没有可用修复版本。安全审计保持非零，没有新增忽略列表、虚构升级版本或私有替代包；CI 的安全步骤仍需等待上游修复。这与功能门禁通过是两个结论。

尚需独立演进的工作：Cookie 认证及真实租户隔离需要后端；组件挂载测试、覆盖率与 a11y 自动化属于测试补位；跨架构分支应按其构建差异单独核验。已有两个 i18n patch 保持固定版本和真实编译回归，升级时先验证查询模块、离线缓存及文本转义，再依据上游实现移除，不能先删补丁导致功能倒退。通用响应/分页模型应以已确认接口契约收敛，避免为不同业务返回体建立宽泛基类。
