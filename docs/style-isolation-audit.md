# 样式隔离与页面体验审查

## 对照 2.5 及更早版本后的修复（2026-10-06）

本次按 `v2.5.0` 的原始锁文件建立独立工作目录，安装发布时的组件库 **0.10.3**、布局 **2.3.2** 与主题 **0.4.0**，不使用当前仓库的源码别名，也不修改旧版页面和样式。旧服务使用 1989 端口，当前服务仍保留 1988。对照只调整旧测试服务的自动打开选项、使用关闭翻译的开发配置，并在独立浏览器中注入测试管理员会话。

在同一台 Chrome **154.0.8037.98**、相同精致亮色主题和 **3437×1190** 视口下，原版 2.5 在 DPR1/DPR2 都复现了步骤正文和导航大面积未绘制；DOM 与路由正常，浏览器没有页面脚本异常。旧版子路由实际注册为 `/steps`，当前版为 `/demo/steps`，对照使用各版本真实路由，并先完成菜单初始化，避免将旧版初次路由回退误认为样式故障。

历史核对表明，卡片头部和 custom-card 的全局模糊由 `b05b143` 引入，**2.4 与 2.5 中该文件完全相同**；2.3 尚无此文件。主题包 0.4.0 与 0.6.1 的精致风格 CSS 基本一致，新增部分主要是减少动画的偏好支持。因此不能将这个规则说成此次升级新增，也不能凭以前正常使用就排除旧规则在当前浏览器及视口组合下触发问题。此前通过只移除触发规则的负面对照确认原因，本轮原始 2.5 对照补充了历史证据。用户以前浏览器版本和窗口状态未留存，不据此推断当时一定存在异常。

同时对照实际 npm 发布的 0.10.3 tarball：整包 CSS 有 **200 条未编译的 `:deep()` 选择器**，其构建会把组件 `index.scss` 再转发到全局入口，绕开 SFC 的 scoped 编译。当前已移除此重复聚合，工具类和图标也在所属 SFC 内编译。整包预加载改成按需加载本身没有复现上述绘制缺失，但它会让第三方全局规则在进入编辑器后才生效，必须检查最终 CSS，不能只检查组件自有源码。

本轮继续锁定第三方的真实越界：加载 Markdown 页后，组件树之外的 `.animation`、`.zoom-in`、`.zoom-out` 被供应商 CSS 改成 0.15 秒、forwards 动画；修复前的浏览器回归明确失败。另有 WangEditor 裸 `.no-scroll { width: 100% }` 和 Leaflet 裸 `.lvml`。它们没有被冒充为整页缺失的唯一原因，但确实超出组件边界。

修复位于组件库发布构建：Markdown 类限定到 `.md-editor-modal`，两个通用关键帧名称使用组件前缀；no-scroll 限定到 `.w-e-text-container`，旧 VML 限定到地图容器。保留挂载在 body 的 Markdown 弹层和图片预览，未用宿主 `.c-markdown` 包裹 Teleport，也未删除供应商样式。七份供应商 CSS 都经过命名空间检查，全量、独立和 Form/Table 传递依赖入口共用同一处理结果；后续依赖升级新增裸全局规则时构建失败。

组件库版本升为 **0.13.5**，项目已固定引入新的不可变 tarball，来源与摘要见 [消费说明](../vendor/README.md)。新增回归在真实安装包上依次进入 Markdown、富文本、地图，检查宿主同名类的计算样式不变，再返回步骤页核对实际绘制。检测与隔离均在构建或测试进程，不增加业务运行时监听或遍历开销。

验证结果：项目完整 `verify` 通过（117 项测试、101 个 SFC 的样式检查、类型检查及两种模式构建）；组件库完整 `verify` 通过（152 项测试、发布入口、消费类型及体积检查）。本轮安装后的 Chrome 普通屏/高分屏冷加载、主题和供应商边界 6 项检查，以及 78 个菜单入口的连续检查和六种布局浮层交互 7 项检查均通过；CI 默认生产预览的供应商隔离检查也通过。Markdown 裁剪弹层在 body 中正常居中显示，关闭后宿主样式不变。逐页截图保留了外链不可达、演示数据与未接入业务接口的实际状态，没有将这些状态改成虚假成功。

## 再次反馈后的实际服务复核（2026-10-06）

本次继续核对实际运行的 1988 服务，安装产物仍为组件库 0.13.4。分别使用本机 Chrome 的普通屏、高分屏，以及有界面的 Chrome 窗口检查；步骤页当前正文、导航、卡片中下部正常绘制。将已删除的卡片头部 `blur(4px)` 仅注入独立测试上下文做负面对照，截图再次丢失正文：新的像素检查在当前代码记录 117 个文字像素，在旧规则对照中记录 0，证明检查确实能识别这类 DOM 可见但未绘制的故障。对照不写入项目或用户页面。

扩大检查范围到六种布局、搜索和引导打开后关闭、内联菜单收起/展开/悬停，以及右侧菜单面板打开后关闭；逐张滚动检查七张卡片的正文，并检查侧栏当前可见的最下方菜单，而不是只看第一个步骤与「首页」。普通屏、高分屏的这些状态均通过。混合布局的二级菜单正常覆盖左侧内容，正文检查前通过菜单入口收起它，避免把预期遮挡误判为绘制缺失。

回归取实际截图中的背景颜色，并组合文字 RGBA 与祖先 opacity，避免渐变菜单和未完成步骤的半透明文字造成误判；文字外侧取样与基于对比度的阈值同时防止将背景本身算作文字。新增检查只运行在开发测试进程，不增加业务页面监听、运行时修补或额外绘制开销。

本轮重新完成 78 个菜单入口的连续检查（73 个站内页面、5 个外链入口），高分屏下公共导航及返回步骤页的实际绘制全部通过；另在生产预览的 CI 默认浏览器与视口下验证新增六种布局检查，6 项通过。样式边界检查、E2E TypeScript 检查与 ESLint 通过。

1988 开发服务已重新启动，让已连接的开发客户端重新加载模块。本次没有在当前服务新开的浏览器上下文中再次复现用户截图，因此没有凭同一张截图断言用户的原窗口仍在运行旧样式；原窗口是否仍有其他触发条件，需要以更新后的实际状态为准。

## 截图异常复现与根因修复（2026-10-06 追加）

用户再次报告步骤页正文和侧栏大面积缺失后，本次使用本机 Google Chrome 154.0.8037.98、3437×1190 的独立浏览器上下文访问实际 1988 服务，已复现相同现象。上一轮使用的 Playwright Chromium 检查未捕获它；DOM 可见与计算样式正确不能替代实际绘制验证。

已确认的触发规则位于项目 `src/styles/glass-morphism-app.scss`：`[data-design-style='glass-morphism'] .n-card-header` 上的 `backdrop-filter: blur(4px)` 及 WebKit 同名属性。`@robot-admin/theme` 的精致卡片风格使用底色和阴影，项目旧增强层却全局叠加了常驻模糊。

普通屏对照使用三个全新的页面上下文：原样页面出现缺失；仅移除卡片头部模糊时，侧栏、导航、卡片背景、步骤文字与操作按钮全部恢复；仅移除搜索按钮模糊时，异常仍在。单独移除 contain、常驻 will-change 或动画也没有完整修复。步骤、日期、城市组件本身不需要逐页打补丁。

随后高分屏检查确认第二个独立触发点：组件库 C_GlobalSearch 的常驻 `.robot-search-trigger` 使用 `backdrop-filter: blur(20px)`。在 DPR2 下将窗口从 1720×640 放大到 3437×1190 后，正文底部会被错误裁切，部分帧整体为空；DOM 的边界和滚动高度仍正确。只移除这个按钮的模糊，即恢复底部注册说明与按钮，效果与关闭全部模糊的对照一致。此缺陷在组件库源码修复，版本升级至 **0.13.4**，项目已经通过不可变 tarball 引入，未添加宿主覆盖样式。

这两处属于常驻背景采样引发的 Chrome 合成绘制异常，外观像“样式污染”，并非页面选择器把侧栏改成透明。修复删除卡片头部及搜索按钮的背景采样，同时清理 custom-card 常驻模糊、重复的 Drawer/Popover 模糊，以及依赖旧版 `--dt-card-bg` / `--dt-blur` 的覆盖。卡片保留底色、细线、圆角和阴影；浮层效果由现有主题包及搜索组件负责，未全局禁用模糊，也未修改每个演示页面。

- `check:styles` 现在同时编译全局入口，阻止全局规则给常驻卡片重新叠加背景采样，覆盖 101 个 SFC、93 个样式块及主样式入口。
- 新增 `e2e/render-integrity.pw.ts` 与 `playwright.render.config.ts`：截图取文字区域像素，而不是只检查 `toBeVisible()`。原版本即使 DOM 断言通过，步骤文字像素为 0，测试失败；高分屏滚动回归也在 0.13.3 失败。PNG 在测试进程读取，不向被测页面注入大画布；新增依赖仅用于开发测试。
- 开发与生产预览服务已完成 73 个站内页面和 5 个外链入口的连续导航，每页之后返回步骤页核对正文及公共导航的实际绘制，并逐页审阅截图；步骤、日期、城市页面截图正常。外链可能自动返回来源页，检查范围是入口和返回后的宿主绘制。
- 已通过本机 Chrome 的 DPR1/DPR2 及 Chromium 的冷加载检查、三种设计风格、亮暗主题与菜单配色组合，以及 1720×640 / 3437×1190 窗口变化和滚动。像素检查先合成半透明文字与祖先背景，避免将正常暗色文字误判为缺失。
- CI 的常规浏览器检查会包含逐页绘制测试，并增加 `chromium-retina` 冷加载、主题、缩放及滚动回归。项目完整 `verify` 通过（117 项测试），组件库完整 `verify` 通过（143 项测试）；双模式构建、类型、样式及体积检查通过。

本次检查针对绘制完整性，不能替代后端流程、外链服务和全部业务交互验收。浏览器回归可复用已启动的开发或预览服务：

```sh
bunx playwright install chromium --only-shell
bunx playwright test --config playwright.render.config.ts --project chrome
bunx playwright test --config playwright.render.config.ts --project chrome-retina --grep '冷加载|主题'
RENDER_BASE_URL=http://127.0.0.1:4173 bunx playwright test --config playwright.render.config.ts --project chrome
```

Chrome 项目使用本机已安装的 Chrome；CI 可使用安装后的 `--project chromium`。下文保留上一轮发布、图标及页面设计检查记录；当时“原始截图未稳定复现”的限制已由本节复现与对照验证补充。

前三类问题属于真实样式污染或发布缺失。安装状态不一致和主题热更新是进一步风险，不能据此断言它们就是用户截图的唯一原因。

最后还核对了用户实际访问的 1988 服务：它确实仍输出 0.13.2 的虚拟项目信息和旧菜单模块，尽管磁盘已经更新。触碰配置没有使这台旧进程重新读取模块，因此本轮重启了该开发服务并保留 1988 端口；重新请求后已确认版本 0.13.3、当前产物摘要和菜单修复代码一致。新增安装清单监听器已经在新进程中生效，避免之后继续依赖手工重启。浏览器刷新与开发服务清空模块图是两件不同的事。

另修复右键菜单的异步滚动竞态：打开前的位置变化可能在打开后才发出 scroll 通知。组件记录调用目标祖先的位置，过期通知与无关区域滚动不再关闭新菜单；目标真正移动仍关闭。菜单及子菜单获得、移动和恢复焦点均使用 preventScroll。音频组件离开 KeepAlive 页面时暂停实际 Audio，取消迟到的播放状态更新。

## 防止再次出现

- 项目新增 `bun run check:styles`，编译每个 Vue 样式块，检查实际输出选择器，覆盖 101 个 SFC、93 个样式块（其中视图 88 个）。既检查 scoped 标记，也检查全局选择器的命名空间。
- 组件库在合并发布 CSS 前检查自身选择器边界，禁止裸标签、通用状态类和未编译的 deep/global 选择器进入发布产物；全局变量只能使用组件前缀。第三方 CSS 在此后按既有方式合并，未宣称其全部语义已被自动证明安全。
- 项目首帧生成自身静态工具类和图标，懒路由不再依赖进入页面后的一次 CSS 热更新才具备基础样式。保留现有动态图标白名单，没有扫描整个 node_modules。
- 浏览器回归覆盖首次进入、连续切页返回、断网图标、失效图片、尺寸和实际场景操作；构建与 CSS 边界检查已纳入 verify。

库自身工具类带 SFC 作用域。独立消费页中宿主同名 flex、gap、Sortable 状态未被改变，日期组件内部仍具有正确布局。生成器只在构建时运行，浏览器不需要额外运行 UnoCSS 生成器。

## 检查范围和限制

- 路由清单中的 73 个非外链叶子页面分别进行了进入检查、截图审阅与连续 SPA 切页检查。静态样式审查覆盖了路由之外的视图、布局和局部组件，不只检查用户列出的几页。
- 检查过 1720×640 / DPR2 与 3440×1280 / DPR1 的连续访问，并在之后返回步骤、日期、城市、图标和首页检查侧栏、文字颜色、卡片、图标和遮罩；另外检查三种设计风格、亮暗主题和菜单配色组合。
- 初轮尚未稳定复现整页“侧栏一起变淡、刷新后仍不完整”的截图现象；本次已使用本机 Chrome 复现，并完成本报告顶部所述的两组对照及根因修复。
- 部分在切页 500ms 拍摄的截图正文透明，核对为布局包 out-in 的离场 300ms、入场 300ms 阶段；等待动画结束后正文恢复，没有观察到该动画永久卡住。此现象与整页主题失色分别记录。
- 页面可进入和没有 pageerror，不等于每个后端流程已验收。地图、远程媒体、系统管理接口、跨浏览器与弱网仍有各自外部条件。远程观测接口未配置的三个浏览器场景按现有测试条件跳过。
- 六个重做页面在 1600/3440 宽度检查未出现页面横向溢出。390px 且侧栏保持 220px 展开时，部分旧布局只剩约 138px 内容宽，仍有移动端适配空间；这项列入后续工作，没有宣称所有手机布局已经通过。
