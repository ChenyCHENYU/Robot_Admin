# 组件库 0.17.6 编辑契约与回归验收

本次集中修复跨编辑模式的一致性，业务配置继续沿用 `required`、`editProps.rules` 与 `config.edit`。

## 行为与使用方式

| 能力         | 修复结果                                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 表格功能列   | 选择、展开、序号、操作列自动排除于编辑字段；业务列 `editable: false` 保持只读。使用侧无需额外过滤列。                                 |
| 编辑校验     | 弹窗、行、单元格共用列规则提取，必填与自定义规则均保留。类型、嵌套、转换、Promise 和异步 callback 使用 Naive 同源引擎。               |
| 校验状态     | 非法输入保留草稿并提示原因，校验期间禁用内置控件，修正后可继续保存；0 和 false 仍有效。现有重复提交、异步切换与数据刷新隔离继续保留。 |
| 公开实例类型 | C_Time 的 startTime/endTime/singleTime 直接读取数值或 null；C_Menu 的 menuRef 直接读取原生菜单实例或 null。内部组合函数仍保留 Ref。   |
| 工作流       | 节点配置与整体校验共用完整性判断，拒绝空白条件、缺失字段和无效操作符；数值条件按字符串格式传入，例如 `value: '0'`。                   |

Robot_Admin 的 CRUD 表格直接加入选择和序号列，继续只在业务列维护一份必填及自定义规则。异步校验推荐返回 Promise，控件的 min/max 等界面约束需要配套规则才能保护程序化赋值。

## 页面验收

在「组件演示 → 表格管理 → 表格」中：

1. 默认弹窗模式，确认表格有复选框和序号，打开编辑仍只有 10 个业务字段。
2. 姓名输入单字符、邮箱输入非法地址，保存应被阻止；修正后能够保存并更新列表。
3. 切换「仅行编辑」，清空姓名或输入单字符，保存保留当前草稿；修正后退出编辑。
4. 切换「仅单元格编辑」，同样验证必填、长度规则与修正保存。
5. 切换编辑模式与密度，确认旧草稿不会串到新模式，原有展开表间距保持。

## 工程边界

组件库已通过 322 条核心测试、300 条组件挂载回归，ESM/CJS 与 Node16/NodeNext 消费检查通过；另在 Node 中实际执行了两种格式的编辑校验。显式 any 经语法树统计从 178 降至 157，质量门禁同步收紧总量与核心组件预算。

按需加载仍有效，校验引擎在编辑校验时加载。表格基础入口 gzip 226.4 KiB（包含 Vue/Naive UI），在 250 KiB 预算内；其他三个已测入口体积保持原值。类型与规则修复没有移除旧兼容入口。

应用版本与正式 CHANGELOG 继续由 Release Please 管理。main/dev 为本轮同步范围，其他架构分支仍需独立迁移与验证。
