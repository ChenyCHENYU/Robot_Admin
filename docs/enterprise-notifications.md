# 企业消息中心

入口为顶部铃铛的“查看筛选下全部”和用户菜单的“消息中心”，地址 `/account/messages`。顶部预览与页面均提供通用消息、审批流程和独立的未读、已读、待办、已办筛选。页面需要有效登录，属于账户自助页面，不要求额外业务菜单；消息管理和审批能力由服务适配器授权。

## 开箱演示

公开演示继续使用项目既有的 `demo / mock` 部署配置，无需后端。消息、已读、星标、归档、待办办理、草稿、模板、投递记录、审计和通知偏好按用户 ID、租户和公司隔离，保存在当前浏览器。

“演示控制”默认折叠，可生成通知或待办、模拟离线、让下一次指定操作失败，以及重置当前作用域。失败不会清空已加载的内容，可以恢复连接或再次操作。

演示包含待我审批、我已审批、我发起的、抄送给我，以及通过、驳回、退回、撤回、取消、超期和普通业务待办等场景。已有浏览器快照通过 `seedRevision` 在存储事务中补充这些独立场景一次，保留原有阅读、归档、删除、草稿和偏好；不要求清空浏览器。升级后删除的场景不会再次补回。

发送先保存草稿，再明确确认发送。模板可以复用和维护；发送记录支持查看各通道结果、重试失败通道和撤回。站内信、邮件、短信和企业微信均为本地模拟，部门、公司受众也只给当前演示账户生成副本。演示不会对真实用户投递。

演示定时任务只在应用运行时检查，页面恢复后补检查到期任务。浏览器关闭期间没有后台调度或投递服务；正式调度、去重、通知送达和业务审计必须由后端实现。

## 分层和状态

| 层       | 位置                        | 职责                                                               |
| -------- | --------------------------- | ------------------------------------------------------------------ |
| 通用组件 | `C_NotificationCenter`      | 保留通用通知协议，供独立通知场景使用，不依赖应用审批业务           |
| 应用入口 | `C_NotificationBell`        | 应用消息预览壳，消费共享 Store 的业务分类、状态、统计及筛选        |
| 领域状态 | `s_notificationStore`       | 一份状态、预览与完整查询分离、身份代次、请求取消、订阅和轮询所有权 |
| 服务契约 | `notifications.contract.ts` | 消息、统计、命令、模板、发送、投递、审计和偏好                     |
| 演示适配 | `notifications.demo*.ts`    | 持久化事务、跨标签页通知、受控故障和模拟投递                       |
| 远端适配 | `notifications.remote.ts`   | 通过统一 request-core 请求未来消息服务，不回退演示                 |

本轮对照了 lowcode 与 wl-ui-public 的业务分类、四类阅读/办理视图和个人审批中心。业务分类、消息性质、阅读、待办办理、审批结果、参与关系与通道投递分别建模：

| 维度     | 字段                    | 值或含义                                                           |
| -------- | ----------------------- | ------------------------------------------------------------------ |
| 业务分类 | `topic`                 | `general / workflow`；旧消息由流程信息兼容推断                     |
| 消息性质 | `category`              | `system / business / alarm`，与业务分类独立                        |
| 阅读     | `readAt`                | 未读、已读；打开详情仅更新阅读                                     |
| 普通待办 | `taskStatus`            | `pending / in_progress / done / cancelled`                         |
| 审批结果 | `workflow.status`       | `pending / approved / rejected / returned / withdrawn / cancelled` |
| 参与关系 | `workflow.relationship` | `assignee / initiator / cc`；抄送及我发起的流程不计为待我办理      |
| 投递     | `delivery.status`       | 发送治理的通道结果，不充当审批或阅读状态                           |

列表展示跨页连续序号、主题摘要、业务单号、阅读与办理两列状态。审批详情展示实例、发起人、当前节点、截止时间与意见时间线。普通待办可开始、完成、取消；审批由受权审批人同意、驳回、退回，发起人可撤回，抄送只读。驳回或退回必须填写意见，流程命令校验当前版本并记录审计；普通完成待办不能推进审批。

这里提供的是消息工作台和受控审批演示，未移植 lowcode 的流程设计器或生产审批引擎。当前本地同意操作直接结束示例实例；多节点推进、会签、转办、代理、加签、催办、撤回规则和真实业务联动由正式流程服务负责。客户端展示的关系和可用按钮不能替代服务端授权。

全局统计与分类未读数独立于当前分页和筛选。`byTopic` 是未归档分类总数；`workflowPending` 是待我审批数量。旧远端缺少这些可选统计时显示未知，不用当前页或预览条数推算。“全部已读”和“清空”携带业务分类及调用时的收件版本截止值，保留随后新到达的消息。清空针对未归档收件，不删除归档记录。顶部独立查询当前筛选最近 20 条，标明预览边界；完整检索和分页由收件箱承接，跳转保留业务分类与状态。

同一用户和公司下多个视图通过 `acquire()` 共享同步生命周期。切换账户或公司会取消旧请求并清理内存状态，迟到响应不能写回新作用域。浏览器持久化仅服务于演示，不能作为生产授权依据。

## 未来后端接入

`staging / application / remote` 使用 HTTP 适配器。当前仓库提供前端契约；它不表示 Robot_Cloud 已实现这些消息接口。服务不存在时页面明确展示错误，保留登录和其他页面使用，不创建假收件或反复弹出全局错误。

详细端点和模型见 [页面接口说明](../src/views/account/messages/api.md)。所有返回包裹遵循项目 `ApiResponse`；身份、租户、公司及接收者范围由服务端会话确认，不信任客户端声明的用户和角色。`capabilities.manage/preferences/workflow` 只有在服务返回明确授权后开放；未约定实时补偿传输时采用可见页面轮询与联网恢复刷新。

消息正文只保留白名单排版标签，脚本、事件、宿主样式、远程图片、表单和正文外链均移除。附件单独处理，真实附件仍需要可用的服务端授权下载协议。业务入口必须是已注册且当前有权限的站内路由。

后端接入还需验证幂等命令、版本冲突、收件游标、授权下载、通道工作进程和定时任务、重连补偿、数据保留与可观测性。前端演示投递记录不构成真实送达证据。

创建模板和草稿同样携带 `operationId`，未知 ACK 的重试保留原幂等键。写入已经确认但随后的同步失败时，保留成功结果并提示刷新，避免重复创建。演示创建结果仅缓存最近 32 条；正式服务需要持久化幂等记录并返回原实体。

## 校验

`bun run verify` 覆盖静态、类型、领域行为、挂载和两种部署构建；`bun run test:e2e` 使用正式产物验证演示闭环和独立的 HTTP fixture。富文本安全使用真实 Chromium 检查；模拟 DOM 的结果不作为浏览器安全证明。远端 fixture 证明适配协议和界面行为，真实服务接入后仍需端到端联调。
